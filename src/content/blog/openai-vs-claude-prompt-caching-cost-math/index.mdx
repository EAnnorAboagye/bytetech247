## Quick Answer

OpenAI's GPT-5.6 caching charges a 1.25x premium on cache writes, with roughly a 90% discount on reads. Anthropic's Claude caching offers a comparable read discount with no documented separate write premium. The two are no longer comparable on a single discount percentage; model both the write and read cost before picking a provider based on caching.

## What's actually changing

This is a synthesis cluster, not a single dated announcement: it pulls together [GPT-5.6's new caching structure](/ai-productivity/gpt-5-6-prompt-cache-write-premium/) and Anthropic's existing caching structure to compare the two directly, drawing on third-party cost-math coverage (ofox.ai) rather than either provider's primary pricing page.

OpenAI's GPT-5.6 requires explicit cache breakpoints and charges a reported 1.25x premium on the first write to a breakpoint, while reads against an established cache entry get roughly a 90% discount off the standard input rate. Anthropic's Claude caching structure offers a comparable read-side discount, up to roughly 90% off cached input, without a separate documented write premium. That difference is the whole point of this comparison: a single "discount percentage" no longer describes either provider's caching economics on its own.

## Fix it: model the write side, not just the read discount

Picking a provider based on caching-friendliness used to be a simple read-discount comparison. It no longer is. OpenAI's write premium means the real cost of caching a given prefix depends on how many times it gets reused before expiring: reuse it enough times and the write premium is a rounding error against the accumulated read savings; reuse it once or twice and the premium may cost more than caching saved.

Anthropic's caching, without a documented write premium, has a simpler cost model for low-reuse cases specifically. For high-reuse workloads, both providers' read-side discounts land in a similar range, so the provider choice comes down to other factors, not caching cost alone.
